## 1. 프로젝트 개요

기온은 시민의 이동 방식과 이동 수요에 영향을 줄 수 있는 주요 외부 요인이다.

본 프로젝트에서는 **서울시 공공자전거 따릉이와 서울교통공사 지하철 이용 데이터를 기상청 시간별 기온 데이터와 결합**하여, 기온에 따른 두 교통수단의 이용 패턴을 비교·분석했다.

특히 단순한 일평균 기온과 총 이용량의 관계가 아니라, 동일한 **날짜 × 시간대**를 기준으로 데이터를 결합하여 시간대별 기온과 교통수단 이용량의 관계를 분석하는 데 초점을 맞췄다.

### 핵심 질문

> **기온 변화에 따라 따릉이와 지하철의 이용량 및 시간대별 이용 패턴은 어떻게 달라지는가?**

이를 통해 기온이라는 외부 요인이 두 교통수단의 이용 수요에 미치는 관계를 비교하고, 향후 교통수단 운영 및 수요 예측에 활용할 수 있는 기초 자료를 도출하는 것을 목적으로 한다.

## 4. 데이터 전처리

### 4.1 따릉이 데이터

따릉이 원본 CSV는 파일 크기가 크기 때문에 전체 데이터를 한 번에 메모리에 적재하지 않고 **100,000행 단위 Chunk 처리**를 적용했다.

각 Chunk에서 다음 작업을 수행했다.

1. `대여일시` 결측치 확인
2. `대여일시`를 datetime으로 변환
3. 날짜와 시간 추출
4. 06시~23시 데이터만 필터링
5. `06-07`, `07-08`과 같은 시간대 컬럼 생성
6. `날짜 + 시간대`별 대여건수 집계
7. 모든 Chunk 결과를 `concat`
8. Chunk 경계에서 분리된 동일한 `날짜 + 시간대`를 다시 `groupby`하여 최종 합산

```python
result = (
    chunk.groupby(['날짜', '시간대'])
    .size()
    .reset_index(name='따릉이대여건수')
)
```

Chunk 단위로 집계할 경우 동일한 날짜·시간대의 데이터가 서로 다른 Chunk에 나뉠 수 있기 때문에, 마지막에 다시 `groupby`하여 합산했다.

---

### 4.2 지하철 데이터

지하철 원본 데이터는 시간대별 이용량이 여러 개의 컬럼으로 가로 방향으로 존재한다.

예:

```text
날짜 | 06-07시간대 | 07-08시간대 | 08-09시간대 | ...
```

이를 분석하기 편한 세로 형태로 변환하기 위해 `melt()`를 사용했다.

```python
df_clean = df_clean.melt(
    id_vars=['날짜'],
    value_vars=time_cols,
    var_name='시간대',
    value_name='승차인원'
)
```

변환 후 데이터 구조는 다음과 같다.

```text
날짜        시간대     승차인원
2025-03-01  06-07      ...
2025-03-01  07-08      ...
2025-03-01  08-09      ...
```

이후 역별 데이터를 모두 합산하여 서울시 전체 시간대별 지하철 승차인원을 산출했다.

또한 `승하차구분 == '승차'`인 데이터만 사용하여 지하철 이용량을 **승차인원 기준**으로 정의했다.

### 4.3 기온 데이터

기상청 ASOS 시간자료에서 다음 항목을 사용했다.

* 서울 관측소
* 시간별 기온
* 날짜
* 시간대

기온 데이터 역시 06시~23시 데이터만 사용하고, 다음과 같이 동일한 시간대 키를 생성했다.

```text
06:00 → 06-07
07:00 → 07-08
08:00 → 08-09
...
23:00 → 23-24
```

이를 통해 따릉이·지하철·기온 데이터의 시간대 형식을 통일했다.

## 5. 데이터 결합

전처리된 세 데이터의 공통 키는 다음 두 가지다.

```text
날짜 + 시간대
```

따라서 해당 키를 기준으로 Inner Join을 수행했다.

```python
merged = bicycle.merge(
    subway,
    on=['날짜', '시간대'],
    how='inner'
)

merged = merged.merge(
    temperature,
    on=['날짜', '시간대'],
    how='inner'
)
```

최종 분석 데이터는 다음과 같은 구조를 갖는다.

| 날짜         | 시간대   | 따릉이대여건수 | 지하철승차인원 | 기온(°C) |
| ---------- | ----- | ------: | ------: | -----: |
| 2025-03-01 | 06-07 |     787 |  55,215 |    3.4 |
| 2025-03-01 | 07-08 |     ... |     ... |    ... |

여기에 분석 조건을 통제하기 위해 다음 파생변수를 추가했다.

* 요일
* 요일명
* 주말여부
* 공휴일여부

한국 공휴일 및 대체공휴일은 `holidays` 라이브러리를 사용하여 처리했다.

## 6. 분석 방법

### 6.1 평일·비공휴일 기준 분석

교통수단 이용량은 평일과 주말의 생활 패턴 자체가 다르기 때문에 기본 분석 조건을 **평일·비공휴일**로 설정했다.

```python
analysis_df = df[
    (~df['주말여부']) &
    (~df['공휴일여부'])
].copy()
```

대시보드에서는 필요에 따라 전체·주말·공휴일까지 조건을 변경할 수 있다.

---

### 6.2 시간대별 이용 패턴

각 시간대의 절대 이용량만 비교할 경우 따릉이와 지하철의 규모 차이가 크기 때문에 직접적인 비교가 어렵다.

따라서 각 교통수단의 전체 평균 이용량을 **100**으로 설정하고 상대적인 이용 수준을 지수화했다.

```text
이용지수 = 해당 그룹 평균 이용량 / 전체 평균 이용량 × 100
```

예를 들어 이용지수가 120이라면 해당 시간대의 평균 이용량이 전체 평균보다 약 20% 높은 것을 의미한다.

이를 통해 따릉이와 지하철의 시간대별 수요 구조를 비교했다.

---

### 6.3 기온과 이용량의 상관관계

기온과 이용량의 관계를 확인하기 위해 **Spearman 순위상관계수**를 사용했다.

Spearman 상관계수는 두 변수의 실제 값 자체보다 **순위의 변화가 얼마나 함께 움직이는지**를 측정하는 비모수적 상관계수다.

```text
-1 ≤ ρ ≤ +1
```

* `ρ > 0` : 기온이 높아질수록 이용량도 증가하는 경향
* `ρ < 0` : 기온이 높아질수록 이용량은 감소하는 경향
* `ρ ≈ 0` : 단조로운 관계가 약함
* `|ρ|`가 클수록 순위 기준의 관계가 강함

본 프로젝트에서는 다음 두 관계를 각각 계산했다.

```text
기온 ↔ 따릉이대여건수
기온 ↔ 지하철승차인원
```

> **상관관계는 인과관계를 의미하지 않는다.**
> 기온과 이용량 사이에 상관관계가 관찰되더라도 강수량, 미세먼지, 휴일, 계절성, 행사, 출퇴근 패턴 등 다른 요인의 영향을 배제한 것은 아니다.

---

### 6.4 기온 구간별 이용지수

기온을 다음 구간으로 나누어 각 구간의 평균 이용량을 비교했다.

```text
0°C 미만
0~5°C
5~10°C
10~15°C
15~20°C
20~25°C
25~30°C
30°C 이상
```

각 기온 구간에서도 전체 평균을 100으로 두고 이용지수를 계산하여, 특정 기온 조건에서 평소보다 이용량이 높은지 낮은지를 비교했다.

---

### 6.5 월 × 시간대 분석

3월·6월·9월·12월을 기준으로 월별·시간대별 평균 이용량을 히트맵으로 시각화했다.

이를 통해 다음을 확인할 수 있도록 구성했다.

* 계절에 따른 이용량 변화
* 시간대별 이용 패턴
* 따릉이와 지하철의 이용 구조 차이
* 특정 월의 특정 시간대 수요 집중 여부

## 7. 주요 분석 결과

본 프로젝트는 단순히 하나의 상관계수만 제시하는 것이 아니라 다음 네 가지 관점에서 결과를 확인하도록 구성했다.

### ① 시간대별 이용 패턴

따릉이와 지하철은 동일한 서울시 이동수단이지만 시간대별 수요 구조가 다르다.

각 교통수단의 평균 이용량을 100으로 표준화하여 시간대별 상대 이용 수준을 비교함으로써, **절대적인 이용량 규모가 다른 두 교통수단의 패턴을 동일한 기준에서 비교**할 수 있도록 했다.

### ② 기온과 이용량의 관계

기온과 따릉이·지하철 이용량 각각에 대해 Spearman 상관계수를 계산하고 산점도와 추세선을 함께 제공한다.

이를 통해 단순히 "기온이 높으면 이용량이 증가한다"와 같은 가정을 전제하지 않고, 실제 데이터에서 관찰되는 관계의 **방향과 강도**를 확인할 수 있도록 했다.

### ③ 기온 구간별 이용 변화

연속적인 기온값만으로는 특정 온도 범위에서 이용량이 어떻게 달라지는지 직관적으로 파악하기 어렵기 때문에 기온을 5°C 단위 구간으로 분류했다.

각 구간의 이용지수를 비교하여 **어떤 기온 범위에서 두 교통수단의 이용 수준이 상대적으로 높거나 낮은지** 확인할 수 있다.

### ④ 월 × 시간대 패턴

3·6·9·12월을 비교하여 계절 변화와 시간대 변화가 결합된 이용 패턴을 확인했다.

## 12. 데이터 처리 시 고려사항

### 대용량 CSV 처리

따릉이 대여이력 데이터는 파일 크기가 크기 때문에 `pd.read_csv()`의 `chunksize` 옵션을 이용해 100,000행씩 나누어 처리했다.

이를 통해 전체 데이터를 한 번에 메모리에 올리는 부담을 줄였다.

### Chunk 경계 문제

Chunk별로 `날짜 + 시간대`를 집계한 뒤 단순히 결과를 이어 붙이는 것만으로는 최종 집계가 완성되지 않는다.

예를 들어 하나의 시간대 데이터가 Chunk A와 Chunk B에 나뉘어 존재할 수 있다.

따라서:

```text
Chunk별 groupby
      ↓
concat
      ↓
날짜 + 시간대 기준 재 groupby
      ↓
최종 합산
```

과정을 적용했다.

### 데이터 구조 통일

세 데이터의 원본 구조가 서로 다르기 때문에 최종적으로 다음 형태로 통일했다.

```text
날짜 | 시간대 | 지표값
```

이를 기반으로 `날짜 + 시간대`를 공통 Join Key로 사용했다.

## 13. 한계 및 개선 방향

본 분석은 **기온과 교통수단 이용량의 관계를 탐색적으로 확인하는 분석**이며, 기온의 인과효과를 추정하는 연구는 아니다.

주요 한계는 다음과 같다.

### ① 분석 기간

2025년 중 3·6·9·12월을 사용했기 때문에 1년 전체의 모든 날짜를 분석한 것은 아니다.

향후 1~12월 전체 데이터를 사용하면 계절별 차이를 보다 안정적으로 분석할 수 있다.

### ② 기상 변수

현재 분석에서는 주로 기온만 사용했다.

실제 이동수요에는 다음과 같은 요인도 영향을 줄 수 있다.

* 강수량
* 습도
* 풍속
* 미세먼지
* 적설
* 폭염·한파 등 극한기상

향후 이러한 변수를 추가하면 기온의 독립적인 영향을 보다 정교하게 분석할 수 있다.

### ③ 교통수단별 데이터 특성

따릉이는 **대여건수**, 지하철은 **승차인원**을 사용하기 때문에 두 지표의 절대값을 직접 비교하는 것은 적절하지 않다.

따라서 본 프로젝트에서는 교통수단별 평균을 100으로 정규화한 **이용지수**를 사용하여 패턴을 비교했다.

### ④ 인과관계

상관계수가 높다고 해서 기온이 이용량 변화의 직접적인 원인이라고 단정할 수 없다.

향후에는 요일, 시간대, 계절, 강수량 등의 변수를 통제한 회귀분석이나 시계열 분석을 적용할 수 있다.

## 14. 향후 개선 방향

```text
현재
기온
 │
 ├── 따릉이 이용량
 └── 지하철 이용량

            ↓

향후
기온 + 강수량 + 습도 + 풍속 + 미세먼지
                    │
                    ▼
            다변량 분석 / 회귀분석
                    │
                    ▼
             교통수요 예측 모델
                    │
                    ▼
          운영 인력·자원 최적화
```

향후에는 기상 데이터를 확대하고 머신러닝 기반 수요 예측 모델을 적용하여 특정 기상조건에서의 교통수요를 예측하는 방향으로 발전시킬 수 있다.
